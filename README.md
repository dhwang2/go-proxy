# go-proxy-cli

A non-interactive Go CLI for managing proxy protocols, users, routing and services.

Executable: `gproxy`. The project is named go-proxy-cli; the command, the runtime root `/etc/go-proxy` and the `version` output keep the shorter `go-proxy` spelling so existing installations keep working. Use `--json` for agent automation; no terminal UI is required.

## CLI documentation

Read [the agent guide](app/CLI.md) for command syntax, JSON/exit-code contracts, credentials, repeatable operations and verification workflows.

```bash
gproxy init --json
gproxy user add alice --json
gproxy protocol install vless --reality --user alice --port auto --json
gproxy protocol --json
gproxy sub alice --json
gproxy status --probe --json
```

Fresh Reality and ShadowTLS installations select a random, TLS-verified handshake domain from a built-in candidate pool. Existing nodes keep their credentials and domain on repeat operations. Ordinary TLS protocols require a domain you control.

## Development build

`refactor/cli` contains the `v0.2.0-dev` candidate. The published stable release remains separate until the CLI milestone is released.

```bash
cd app
make build VERSION=v0.2.0-dev
make test
./gproxy --help
```

Cross-build on a development/CI machine with `make release` or `make release-arm`; do not compile on a memory-constrained deployment host. Tests use the Go overlay generated by `scripts/generate-test-overlay.sh`.

## Published installation

The installer downloads and verifies a published Linux amd64/arm64 release, then initializes the CLI. It targets the public `dhwang2/go-proxy` releases; set `REPO` to override the source. `gproxy update` checks and replaces the executable from the same place.

```bash
curl -fsSL https://raw.githubusercontent.com/dhwang2/go-proxy/main/app/install.sh | sudo bash
```

## Runtime and resources

The runtime root is `/etc/go-proxy`. Read-only commands use local snapshots by default; public-network probes are explicit. Downloads are streamed, heavy mutations are serialized, and output/operations support cancellation.

The resource target is a shared 2-vCPU, 1-GiB host. Proxy-core and workload consumption are separate from CLI overhead; functionality, response time and actual host pressure must all be verified.

Subscription exports contain connection credentials. Save them with restrictive permissions and keep them out of logs or public reports.
